# MedMind Nexus 合规与安全说明

> 本文说明系统已实现的安全机制与合规对应,以及生产上线前需要客户配合完成的合规改造。

## 一、当前已实现 ✅

### 1.1 身份认证
- ✅ JWT (HS256) 双 token 机制 (access 60min + refresh 7day)
- ✅ bcrypt 密码哈希 (rounds=12, 抗彩虹表攻击)
- ✅ 登录失败计数 `failed_login_attempts` (可扩展为账号锁)
- ✅ MFA TOTP 字段已预留 (`mfa_enabled` / `mfa_secret`)

### 1.2 权限控制
- ✅ 5 角色 RBAC: patient / doctor / pharmacist / admin / researcher
- ✅ FastAPI Depends 注入 + 路由级权限装饰
- ✅ 数据所有权: 患者只能看自己; 医生只能看本人接诊
- ✅ 科研角色: 患者数据自动脱敏

### 1.3 审计日志 (等保三级)
- ✅ `audit_logs` 表完整字段:
  - user_id / username / action / resource_type / resource_id
  - ip_address / user_agent / result / error_message
  - created_at (索引)
- ✅ 所有写操作自动埋点
- ✅ 登录/登出/失败均留痕

### 1.4 传输安全
- ✅ FastAPI CORS 白名单可配置 (默认拒绝)
- ✅ Nginx 部署指南含 TLS 1.3 + HSTS
- ✅ WebSocket 走 wss:// 加密

### 1.5 输入校验
- ✅ Pydantic v2 严格类型校验
- ✅ SQL 注入: SQLAlchemy ORM 全参数化
- ✅ XSS: 前端 textContent + 后端 HTML 转义
- ✅ 文件上传: 文件大小/类型白名单 (Nginx + FastAPI 双层)

### 1.6 AI 风险防护
- ✅ **4 层幻觉防护** (诊断辅助):
  1. Prompt 约束: 禁止编造 ICD/药品
  2. JSON Schema: 严格 Pydantic 校验
  3. 引用回溯: 每条结论 citation
  4. 置信度阈值: <0.6 "需复核"
- ✅ **免责声明**: 所有 AI 输出含"仅供医师参考"
- ✅ **可追溯**: AI 原始草稿 `ai_draft_raw` 留档

### 1.7 异常处理
- ✅ 全局 exception_handler 统一封装
- ✅ 不泄露后端实现细节 (生产模式)
- ✅ 422 字段错误清晰提示

## 二、生产上线需补强 ⚠️

以下为**生产环境合规改造清单**, 当前 demo 已具备扩展能力, 实施时一对一对接:

### 2.1 数据加密
- [ ] **数据库 TDE**: PG 16 `pgcrypto` 或表空间级加密
- [ ] **字段级加密**: 身份证 / 手机号 / 病历正文 (敏感字段)
- [ ] **备份加密**: pg_dump 流式 GPG 加密
- [ ] **密钥管理**: KMS / HashiCorp Vault, 严禁明文 .env

### 2.2 网络隔离
- [ ] DMZ 区与内网隔离, 数据库不暴露公网
- [ ] WAF (Web 应用防火墙): 阿里云 WAF / 长亭雷池
- [ ] DDoS 防护: CDN + Anti-DDoS

### 2.3 访问控制
- [ ] **强制 MFA**: 管理员/医生登录强制 TOTP
- [ ] **IP 白名单**: 管理端只允许院内 IP 访问
- [ ] **会话管理**: Redis 黑名单, 登出立即失效
- [ ] **密码策略**: 最少 12 位 + 大小写数字符号

### 2.4 数据治理
- [ ] **RLS (Row Level Security)**: PG 行级权限
- [ ] **数据脱敏**: 测试库自动脱敏 (Faker)
- [ ] **数据导出审计**: 所有导出操作留痕 + 数字水印
- [ ] **数据保留期**: 病历 ≥15 年, 影像 ≥30 年 (按卫健委)

### 2.5 合规认证
- [ ] **等保三级备案** (重要)
- [ ] **医疗器械二类备案** (AI 辅助决策需要)

## 三、AI 伦理边界

### 3.1 明确边界
本系统 AI 仅作**辅助诊疗建议**, 不替代医生:
- ❌ 不下最终诊断 (终责必须医生)
- ❌ 不直接开方 (必须医生签字)
- ❌ 不代发处方流
- ❌ 不签发医学证明
- ✅ 提供候选诊断 + 循证依据
- ✅ 提供处方审核警示
- ✅ 提供文书草稿

### 3.2 患者知情
- 患者首次使用 AI 功能弹窗告知
- "本次 AI 解读仅供参考" 强制显示
- 患者可选择不使用 AI 功能

### 3.3 黑名单
以下场景**禁止**使用 AI:
- 法医鉴定
- 医疗纠纷举证
- 保险理赔单独依据
- 重大疾病初次诊断 (必须人工首诊)

## 四、应急联系

如发生数据泄露或安全事件:
1. **立即**: 切断对外服务 (`docker compose down`)
2. **30 分钟内**: 通知信息科主任 + 院领导
3. **2 小时内**: 上报当地卫健委 (重大数据泄露)
4. **24 小时内**: 通知受影响患者
5. **72 小时内**: 上报网信部门 (个人信息泄露)

## 五、合规 Q&A

**Q: 系统是否符合 GDPR/HIPAA?**
A: 当前架构具备核心机制, 但未做正式认证。生产前需补强加密+审计+授权 3 项, 然后请第三方合规审计。

**Q: 是否可以做云端 SaaS?**
A: 可以, 但需:
- 数据加密存储 + 传输 + 备份
- 等保三级 + 医疗器械二类
- 与医院签 SLA + 数据处理协议
- 数据归属医院, 不得用于训练模型

**Q: 患者数据能用来训练 AI 吗?**
A: **严禁直接用**。必须先:
- 患者明确授权 (单独勾选)
- 数据去标识化 (k-匿名化 / 差分隐私)
- 伦理委员会批准
- 不出院、本地化训练
