# M1：患者端应用详细设计

## 1. 模块概述

患者端是MedMind Nexus面向患者的入口，包括微信小程序和手机APP两个载体。核心目标是：**让患者在就诊前、中、后都能获得AI辅助，提升就医体验，同时减轻医生工作量**。

## 2. 功能架构

```
患者端应用
├── 首页（个人健康中心）
│   ├── 我的医生/就诊记录
│   ├── 健康档案（脱敏）
│   └── 消息通知
├── AI智能预问诊
│   ├── 症状采集对话
│   ├── 病史采集
│   ├── 用药史/过敏史采集

├── 智能分诊导诊
│   ├── 科室推荐
│   ├── 医生推荐
│   └── 挂号链接跳转
├── 检查报告AI解读
│   ├── 报告上传（拍照/文件）

```

## 3. 核心功能详细设计

### 3.1 AI智能预问诊（核心功能）

#### 3.1.1 功能流程

```
开始 → 选择就诊科室 → AI问候并引导描述症状 → 多轮对话采集信息 
→ 生成预问诊摘要 → 推送医生 → 患者查看医生建议
```

#### 3.1.2 AI Agent设计（预问诊Agent）

**Agent类型**：单Agent（LangChain零样本Agent）+ 规则引擎

**工具集（Tools）**：
- `symptom_checker`：症状合理性检查（调用医学知识库）
- `urgency_assessor`：紧急程度评估（红/黄/绿三色预警）
- `medical_history_collector`：按照SOAP格式采集病史

**Prompt模板**：
```
你是一位专业的医疗预问诊AI助手。

【任务】
通过多轮对话，采集患者的：
1. 主诉（chief complaint）
2. 现病史（history of present illness）
3. 既往史（past medical history）
4. 用药史（current medications）
5. 过敏史（allergies）

【规则】
1. 每次只问1-2个问题
2. 语言通俗易懂，避免专业术语
3. 如果采集到紧急症状（胸痛、呼吸困难、意识障碍、大出血），立即输出"【紧急预警】请立即就医！"并终止采集
4. 采集完成后，输出JSON格式的结构化摘要

【输出格式】
{
  "chief_complaint": "...",
  "history_present_illness": "...",
  "past_history": ["高血压", "糖尿病"],
  "medications": ["二甲双胍 0.5g bid"],
  "allergies": ["青霉素"],
  "urgency": "low|medium|high|emergency"
}

现在开始，问候患者并引导其描述症状。
```

**多轮对话状态管理**：
- 使用LangChain的`ConversationBufferMemory`保存对话历史
- 每个症状实体用NER模型提取并结构化存储

#### 3.1.3 紧急预警规则

| 症状关键词 | 预警级别 | 处理方式 |
|-----------|---------|---------|
| 胸痛、胸闷、呼吸困难 | 紧急（红） | 立即提示就医，不继续采集 |
| 高热（>39℃）超过3天 | 高（橙） | 提示尽快就医，可继续采集 |
| 慢性病常规随访 | 低（绿） | 正常采集流程 |

### 3.2 智能分诊导诊

#### 3.2.1 功能描述
根据患者描述的症状，AI推荐合适的科室和医生，并可直接跳转挂号。

#### 3.2.2 AI推荐算法
1. **症状 → 科室映射**：基于医学知识图谱（Neo4j）
   - 输入：症状列表 `["胸闷", "胸痛"]`
   - 输出：科室推荐 `[("心内科", 0.92), ("呼吸内科", 0.75), ("急诊科", 0.68)]`
2. **科室 → 医生推荐**：基于医生排班、专业方向、患者评价
3. **展示逻辑**：Top3科室 + 每个科室Top2医生

### 3.3 检查报告AI解读

#### 3.3.1 功能流程
```
患者上传报告 → OCR识别 → 结构化提取 → RAG知识库比对 
→ AI生成解读 → 异常预警 → 健康建议
```

#### 3.3.2 OCR识别方案
- **血检/尿检等表格报告**：PaddleOCR（中文医疗场景优化）
- **影像报告（CT/MRI）**：Azure Cognitive Services OCR 或 百度OCR
- **结构化输出**：JSON格式，包含 `检查项目、结果、参考范围、是否正常`

#### 3.3.3 AI解读Prompt
```
你是一位专业的检验报告解读AI助手。

【输入】
以下是患者的检验报告结果：
{{lab_results}}

【任务】
1. 用通俗易懂的语言解释每项结果
2. 标注异常指标（↑或↓），并解释可能的原因
3. 给出生活建议或就医建议
4. 不要给出诊断结论

【输出格式】
## 检验结果解读

### 血常规
- 白细胞（WBC）：6.5 ×10^9/L（正常）
  - 解读：...
- 血红蛋白（HGB）：105 g/L（↓ 偏低）
  - 解读：可能存在贫血，建议...
  
### 总体建议
...
```

### 3.4 用药提醒与随访

#### 3.4.1 用药提醒
- **数据来源**：医生开具的电子处方
- **提醒方式**：
  - 小程序订阅消息（微信服务通知）
  - APP Push通知
  - 短信提醒（备用）
- **提醒内容**：
  ```
  【用药提醒】
  亲爱的张三，您该服用：
  💊 络活喜 5mg × 1片
  🕐 早餐后
  点击查看详情 >
  ```

#### 3.4.2 随访问卷
- **触发条件**：医生在诊后设置随访计划
- **问卷内容**：由AI根据病情动态生成
  - 例如：冠心病术后随访 → 询问胸痛情况、用药依从性、运动耐力等
- **AI分析**：患者填写后，AI生成随访摘要推送给医生

## 4. 数据模型（患者端相关表）

### 4.1 `patients`（患者档案表）
```sql
CREATE TABLE patients (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id),
    real_name_encrypted BYTEA,  -- AES-256加密
    id_card_encrypted BYTEA,
    phone_encrypted BYTEA,
    birth_date DATE,
    gender VARCHAR(10),
    allergy_history JSONB,  -- 过敏史列表
    past_history JSONB,  -- 既往史列表
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
```

### 4.2 `pre_consultations`（预问诊记录表）
```sql
CREATE TABLE pre_consultations (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    patient_id UUID REFERENCES patients(id),
    department VARCHAR(50),
    conversation JSONB,  -- 完整对话记录
    summary JSONB,  -- 结构化摘要
    urgency_level VARCHAR(20),
    status VARCHAR(20) DEFAULT 'pending',  -- pending/completed/cancelled
    doctor_viewed BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP DEFAULT NOW()
);
```

## 5. 技术实现要点

### 5.1 微信小程序端（Taro 4）
- **框架**：Taro 4 + React + TypeScript
- **状态管理**：Zustand（轻量，适合小程序）
- **网络请求**：Taro HTTPClient（封装拦截器，自动携带Token）
- **语音输入**：使用微信小程序原生录音API + 上传到服务端调Whisper API

### 5.2 手机APP端（Flutter）
- **框架**：Flutter 3.x + Riverpod
- **网络层**：Dio（支持Retry、Interceptor）
- **本地存储**：SharedPreferences（轻量缓存）+ SQLite（离线预问诊草稿）
- **推送通知**：Firebase Cloud Messaging（Android）+ APNs（iOS）

### 5.3 关键性能优化
- **预问诊对话**：使用流式输出（Server-Sent Events），减少等待感
- **报告图片上传**：前端压缩（小程序端最大压缩到1MB），断点续传
- **用药提醒**：使用微信订阅消息（无需备案，患者主动订阅）
