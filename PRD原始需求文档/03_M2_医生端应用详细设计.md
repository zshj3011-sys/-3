# M2：医生端应用详细设计

## 1. 模块概述

医生端是MedMind Nexus的核心生产力工具，面向医生、医助、药师等医疗专业人员。**核心价值：让医生节省50%文书时间，获得AI第二诊疗意见，提升诊疗质量和效率**。

支持三端：PC桌面端（Tauri）、Web浏览器端（Next.js）、手机APP端（Flutter）。

## 3. 核心功能详细设计

### 3.1 AI诊间助手（最重要功能）

#### 3.1.1 功能流程图

```
医生点击"开始诊间" → 选择患者 → 系统加载AI预问诊摘要 
→ 开始录音（实时区分医患对话）→ AI实时转写 + 角色分离 
→ AI实时提取关键临床信息 → 问诊结束 → AI生成SOAP病历草稿 
→ 医生审核修改 → AI质控检查 → 保存病历
```

#### 3.1.2 技术架构

**前端录音** → **后端ASR服务** → **角色分离** → **NER实体提取** → **LLM生成病历**

| 组件 | 技术选型 | 说明 |
|------|---------|------|
| 前端录音 | Web Audio API / Tauri录音插件 | 采样率16kHz，单声道 |
| ASR语音识别 | Whisper-large-v3 / 讯飞医疗ASR | 实时流式识别 |
| 角色分离 | PyAnnote / 基于规则的说话人分离 | 区分"医生"和"患者" |
| 医学NER | 微调的BiLSTM-CRF模型 | 提取症状、疾病、药物等实体 |
| 病历生成LLM | DeepSeek-R1 Medical / HuatuoGPT-o1 | 生成SOAP格式病历 |

#### 3.1.3 实时语音转写实现

**前端（Web/PC端）**：
```typescript
// Next.js / Tauri前端
const mediaRecorder = await navigator.mediaDevices.getUserMedia({ audio: true });
const recorder = new MediaRecorder(mediaRecorder.stream);

recorder.ondataavailable = async (event) => {
  // 每2秒发送一次音频块到后端
  const audioChunk = event.data;
  await fetch('/api/asr/stream', {
    method: 'POST',
    body: audioChunk,
    headers: { 'Content-Type': 'audio/webm' }
  });
};

recorder.start(2000); // 每2秒触发一次dataavailable
```

**后端（FastAPI + Whisper）**：
```python
from fastapi import FastAPI, WebSocket
import whisper

app = FastAPI()
model = whisper.load_model("large-v3")

@app.websocket("/ws/asr/stream")
async def asr_stream(websocket: WebSocket):
    await websocket.accept()
    audio_buffer = []
    
    while True:
        audio_chunk = await websocket.receive_bytes()
        audio_buffer.append(audio_chunk)
        
        # 每积累5秒音频，调用一次Whisper
        if len(audio_buffer) >= 50:  # 50 * 100ms = 5s
            audio_data = np.concatenate(audio_buffer)
            result = model.transcribe(audio_data, language="zh")
            
            # 角色分离（简单规则：句子长度判断）
            role = detect_role(result["text"])
            
            await websocket.send_json({
                "role": role,  # "doctor" or "patient"
                "text": result["text"],
                "timestamp": time.time()
            })
            audio_buffer = []
```

#### 3.1.4 病历生成Prompt（关键！）

```
你是一位专业的医疗AI助手，负责根据问诊对话生成符合规范的电子病历。

【输入】
## 问诊对话记录
医生：您好，请描述您的症状。
患者：我最近经常胸闷，尤其是活动后。
医生：这种情况有多久了？
患者：大概两周了。
...（完整对话）...

## 患者基本信息
姓名：张三（脱敏）
性别：男
年龄：45岁
过敏史：青霉素

【任务】
生成SOAP格式的电子病历。

S（Subjective，主诉）：
- 引用患者原话
- 格式："胸闷2周，活动后加重"

O（Objective，客观检查）：
- 如果对话中没有体格检查，填写"未见明显异常"或"[待补充]"
- 如果有生命体征，记录在此

A（Assessment，评估/诊断）：
- 列出Top 3鉴别诊断（按可能性排序）
- 使用ICD-10编码格式
- 例如："I20.0 不稳定型心绞痛"

P（Plan，计划）：
- 建议进一步检查（如：心电图、心肌酶、冠脉CTA）
- 治疗建议（如：注意休息、避免剧烈活动）
- 随访建议（如：3天后复诊）

【要求】
1. 使用专业但简洁的医疗术语
2. 不添加未经对话确认的内容
3. 如果信息不足，在对应字段标注"[需补充]"
4. 诊断建议用"考虑"而非"确诊"
5. 输出严格的JSON格式，方便前端渲染

【输出格式】
{
  "subjective": "...",
  "objective": "...",
  "assessment": [
    {"icd10": "I20.0", "diagnosis": "不稳定型心绞痛", "probability": 0.75},
    {"icd10": "K21.0", "diagnosis": "胃食管反流病", "probability": 0.15},
    {"icd10": "F41.9", "diagnosis": "焦虑状态", "probability": 0.10}
  ],
  "plan": "...",
  "confidence": 0.82
}
```

#### 3.1.6 病历质控AI实现

**质控规则（三层）**：

| 层级 | 规则 | 实现方式 |
|------|------|---------|
| 格式层 | 必须包含SOAP四部分 | 正则表达式检查 |
| 内容层 | 主诉与诊断是否一致、用药与诊断是否匹配 | 知识图谱推理（Neo4j） |
| 合理性层 | 诊断是否符合指南、检查是否合理 | RAG + LLM判断 |

**质控Prompt**：
```

【任务】

1. 完整性：SOAP四部分是否完整？
2. 一致性：主诉、病史、诊断、处方之间是否一致？
3. 合理性：诊断是否符合临床指南？检查是否合理？用药是否对症？
4. 规范性：是否使用了规范的医学术语？ICD-10编码是否正确？

【输入病历】
{{soap_note}}

【输出格式】
```

### 3.2 AI诊断辅助建议

#### 3.2.1 功能描述
在医生输入主诉和病史后，AI提供Top 3鉴别诊断建议，并给出支持/反对证据。

#### 3.2.2 技术实现（RAG + LLM）

**流程**：
1. 提取患者关键临床信息（症状、体征、检查结果）
2. 向量检索相似病例和指南（Milvus）
3. 将检索结果 + 患者信息发给LLM
4. LLM生成鉴别诊断列表（Top 3-5）
5. 每个诊断给出"支持证据"和"需排除的检查"

**Prompt模板**：
```
你是一位经验丰富的临床专家。

【患者信息】
主诉：{{chief_complaint}}
现病史：{{history}}
体格检查：{{physical_exam}}
检查结果：{{lab_results}}

【任务】
给出Top 3鉴别诊断，并为每个诊断列出：
1. 支持证据（症状/体征/检查）
2. 需排除的检查
3. 鉴别诊断要点（与其他诊断的区分）

【输出格式】
JSON数组，按可能性从高到低排序。
```

### 3.3 处方审核与用药建议（药师端核心功能）

#### 3.3.1 功能描述
AI自动检查处方中的用药相互作用、过敏冲突、剂量合理性，并给出建议。

#### 3.3.2 技术实现（知识图谱 + 规则引擎）

**知识图谱构建（Neo4j）**：
```
(:Drug {name: "阿司匹林"})
  -[:CONTRAINDICATED_WITH]-> (:Disease {name: "消化道溃疡"})
  -[:INTERACTS_WITH {severity: "high"}]-> (:Drug {name: "华法林"})
  -[:ALLERGY_REACTION]-> (:Allergen {name: "青霉素"})
```

**处方审核流程**：
```
输入处方 → NER提取药物列表 → 知识图谱查询相互作用 
→ 规则引擎检查剂量 → LLM综合判断 → 输出审核结果
```

**审核结果分级**：
| 级别 | 含义 | 处理方式 |
|------|------|---------|
| 🔴 严重 | 禁忌症、严重相互作用 | 强制医生修改，无法保存 |
| 🟡 警告 | 轻微相互作用、超剂量 | 提示医生确认，可强制保存 |
| 🟢 通过 | 无问题 | 直接通过 |

## 4. 多端协同设计

### 4.1 场景：医生在PC端工作，手机端辅助

**需求**：医生在诊室用PC端（Tauri）看患者、写病历，但在病房查房时用手机APP快速记录。

**技术方案**：
- 使用WebSocket实时同步状态
- 患者信息、病历草稿、AI建议都实时同步到所有端
- 冲突解决：以最后保存的版本为准，冲突时提示医生

### 4.2 数据同步流程

```
PC端操作 → API保存 → 数据库更新 → WebSocket推送 
→ 手机端/Web端实时刷新
```

## 5. 性能与体验优化

### 5.1 关键性能指标（KPI）

| 指标 | 目标值 | 测量方法 |
|------|--------|---------|
| 语音识别延迟（P95） | < 3秒 | 从说话结束到文字出现 |
| 病历生成时间（P95） | < 5秒 | 从结束录音到生成草稿 |
| AI诊断建议响应时间 | < 2秒 | 从点击按钮到显示结果 |
| 处方审核时间 | < 1秒 | 从提交处方到审核结果 |

### 5.2 体验优化技巧

1. **流式输出**：AI生成病历时，逐字显示（像ChatGPT一样），减少等待感
2. **本地缓存**：常用模板、药品库、指南缓存到本地（Tauri/Flutter本地存储）
3. **快捷键**：PC端支持快捷键（Ctrl+S保存、Ctrl+Enter生成病历）
4. **离线模式**：网络不好时，可以先本地记录，网络恢复后同步

## 6. 安全与合规

### 6.1 医生身份认证

- **双因素认证（2FA）**：密码 + 短信验证码 / TOTP（如Google Authenticator）
- **设备绑定**：首次登录新设备需短信验证
- **自动登出**：无操作30分钟后自动登出

### 6.2 操作审计日志

所有以下操作必须记录：
- 登录/登出（时间、IP、设备）
- 查看患者病历（哪个医生、什么时间、哪个患者）
- 修改病历（修改前/后内容、修改原因）
- AI建议采纳/拒绝（记录AI建议内容和最终决策）

**审计日志表示例**：
```sql
CREATE TABLE audit_logs (
    id UUID PRIMARY KEY,
    user_id UUID,
    action VARCHAR(50),  -- 'view_patient', 'edit_record', 'ai_suggestion'
    resource_type VARCHAR(50),  -- 'patient', 'medical_record'
    resource_id UUID,
    details JSONB,  -- 操作详情
    ip_address INET,
    user_agent TEXT,
    created_at TIMESTAMP
);
```
