# M3：管理端应用详细设计

## 1. 模块概述

管理端面向**医院管理员、科室主任、信息科、院长**等管理角色，提供医院运营管理、医疗质量控制、DRG医保控费、系统配置等功能。**核心价值：让医院管理者用数据驱动决策，提升医疗质量，控制医保费用**。

支持载体：Web浏览器端（Next.js 15）为主，PC桌面端（Tauri）为辅。

## 3. 核心功能详细设计

### 3.1 DRG/DIP医保控费系统（最重要功能）

#### 3.1.1 功能背景

**DRG（Diagnosis-Related Groups，疾病诊断相关分组）**：将住院患者按疾病严重程度、治疗方法复杂程度、资源消耗程度分成若干组，以组为单位打包付费。

**痛点**：
- 医院不清楚每个病例的DRG分组和预期费用
- 实际费用超出DRG定额 → 医院亏损
- 医保拒付风险高

**AI价值**：
- 提前预测DRG分组和费用
- 实时监控费用，超支预警
- 分析亏损病案，找出原因

#### 3.1.2 DRG分组预测AI实现

**输入特征**：
```python
features = {
    "主诊断ICD-10编码": "I21.0",
    "次要诊断": ["E11.9", "I10"],  # 糖尿病、高血压
    "手术操作代码": ["00.66"],  # 冠脉造影
    "年龄": 65,
    "性别": "男",
    "入院途径": "急诊",
    "出院状态": "好转",
    "住院天数": 7,
    "总费用": 45000
}
```

**模型选型**：
- **XGBoost / LightGBM**：传统机器学习，可解释性好
- **DeepSeek-R1 Fine-tuning**：如果用LLM，输入病历文本，输出DRG分组
- **推荐方案**：先用XGBoost做预测，再用LLM解释预测理由

**预测流程**：
```
患者入院 → 输入主诊断/手术 → AI预测DRG分组 
→ 查询本市该病种定额 → 计算预期费用 
→ 与实际费用对比 → 超支预警
```

#### 3.1.4 医保费用预警实现

**预警规则引擎**：
```python
def check_medical_insurance_risk(patient_id):
    # 1. 获取患者已发生费用
    costs = get_patient_costs(patient_id)
    
    # 2. 获取DRG定额
    drg_quota = get_drg_quota(patient_id)
    
    # 3. 计算费用进度
    cost_ratio = costs['total'] / drg_quota
    
    # 4. 预警等级
    if cost_ratio > 1.2:
        alert_level = "🔴 严重超支"
        suggestion = "立即停用非必要高值耗材"
    elif cost_ratio > 1.0:
        alert_level = "🟡 即将超支"
        suggestion = "严格控制药品和检查费用"
    else:
        alert_level = "🟢 费用正常"
        suggestion = ""
    
    # 5. 推送预警
    send_alert_to_doctor(patient_id, alert_level, suggestion)
```

**实时费用监控**：
- 每天凌晨计算所有在院患者的费用进度
- 超支风险 > 80% 的患者，推送给主治医师和科主任
- 企业微信/钉钉/短信多渠道推送

### 3.2 医疗质量质控看板

#### 3.2.1 质控指标体系

| 指标类别 | 具体指标 | 计算方式 | 目标值 |
|---------|---------|---------|--------|
| 病历质量 | 病历完整率 | 完整病历数 / 总病历数 | > 95% |
| 病历质量 | 病历按时完成率 | 按时完成数 / 总病历数 | > 90% |
| 合理用药 | 抗生素使用率 | 使用抗生素患者数 / 总患者数 | < 60% |
| 合理用药 | 注射剂使用率 | 使用注射剂患者数 / 总患者数 | < 50% |
| 诊疗规范 | 临床路径入径率 | 入径人数 / 符合条件的患者数 | > 50% |
| 患者安全 | 跌倒发生率 | 跌倒次数 / 总住院天数 | < 0.5‰ |
| 患者安全 | 用药错误次数 | 直接统计 | 0 |

#### 3.2.2 AI病历质控

**自动化检查项**：
1. **完整性检查**：SOAP四部分是否齐全
2. **一致性检查**：主诉与诊断是否一致、用药与诊断是否匹配
3. **时效性检查**：入院记录是否在24小时内完成、手术记录是否在术后24小时内完成
4. **合理性检查**：诊断是否符合指南、检查是否合理、用药是否对症

**实现方式**：
- 规则引擎（确定性检查，如时效性）
- LLM判断（主观性检查，如合理性）

## 4. 数据模型（管理端相关表）

### 4.1 `drg_predictions`（DRG预测表）
```sql
CREATE TABLE drg_predictions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    patient_id UUID REFERENCES patients(id),
    admission_id VARCHAR(50),
    main_diagnosis_icd10 VARCHAR(10),
    procedures JSONB,  -- 手术操作代码数组
    predicted_drg_code VARCHAR(10),
    predicted_drg_name VARCHAR(100),
    predicted_cost DECIMAL(10,2),
    actual_cost DECIMAL(10,2),
    profit_loss DECIMAL(10,2),  -- 盈亏 = 定额 - 实际费用
    created_at TIMESTAMP DEFAULT NOW()
);
```

### 4.2 `quality_control_logs`（质控日志表）
```sql
CREATE TABLE quality_control_logs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    medical_record_id UUID REFERENCES medical_records(id),
    check_type VARCHAR(20),  -- 'completeness' | 'consistency' | 'timeliness' | 'rationality'
    passed BOOLEAN,
    issues JSONB,  -- 发现的问题数组
    quality_score DECIMAL(3,2),  -- 0-1
    checked_by UUID REFERENCES users(id),  -- 如果是AI检查，存AI Agent ID
    created_at TIMESTAMP DEFAULT NOW()
);
```

### 5.2 实时数据推送

**技术方案**：WebSocket + Redis Pub/Sub

```
数据更新 → Redis发布消息 → WebSocket服务器订阅 
→ 推送到前端 → 前端实时刷新图表
```

**代码示例（后端）**：
```python
import redis
import json
from fastapi import WebSocket

r = redis.Redis()

async def push_drg_alert(patient_id, alert_level, suggestion):
    message = {
        "type": "drg_alert",
        "patient_id": patient_id,
        "alert_level": alert_level,
        "suggestion": suggestion,
        "timestamp": time.time()
    }
    r.publish("drg_alerts", json.dumps(message))

@app.websocket("/ws/alerts")
async def alerts_websocket(websocket: WebSocket):
    await websocket.accept()
    pubsub = r.pubsub()
    pubsub.subscribe("drg_alerts")
    
    for message in pubsub.listen():
        if message["type"] == "message":
            await websocket.send_text(message["data"])
```

### 6.2 数据权限（行级权限）

**规则**：
- 科室主任只能看到本科室的数据
- 院长可以看到全院数据
- 医生只能看到自己的患者数据

**实现方式**（PostgreSQL RLS - Row Level Security）：
```sql
-- 启用RLS
ALTER TABLE medical_records ENABLE ROW LEVEL SECURITY;

-- 创建策略：科室主任只能看本科室病历
CREATE POLICY dept_policy ON medical_records
    FOR SELECT
    USING (department_id = current_setting('app.current_department_id')::UUID);
```
